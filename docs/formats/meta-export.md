# Instagram and Facebook Messenger ("Download your information")

Meta's account download, for Instagram and for Facebook. Layout observed on an Instagram download made
2025-09-08 (HTML; 92 threads, 31,251 messages, 631 media files) and a Facebook download made 2025-09-09 (HTML;
11 threads, 44 messages). The JSON variant is described from Meta's documented layout; the importer reads both.
Importer: `src/importers/meta.ts` (platforms `instagram`, `messenger`).

## Where the messages are

```
<root>/
├── your_instagram_activity/messages/      (Instagram)   ─┐ one folder per thread, inside one of:
├── your_facebook_activity/messages/       (Facebook)     │   inbox/  message_requests/  archived_threads/
│     └── <folder>/<thread>/message_1.html               │   e2ee_cutover/  filtered_threads/
│                         message_2.html …                │
│                         photos/ videos/ audio/ gifs/ files/
├── files/ (Instagram logo, page assets)  start_here.html  …
```

Older downloads put `messages/` at the root. `message_1` is the **newest** page, and each page lists its newest
message first; a thread is read from the last page to the first and each page bottom-up.

Media references (`src`, `href`, JSON `uri`) are paths from the download's root (`your_instagram_activity/…`).
When only part of the download is dropped, the folders above it are missing from the paths the converter sees,
so references are matched on their longest tail that exists.

## HTML

Each message is an element with the class token `_a6-g` (`div` on Instagram, `section` on Facebook):

| Part | Element | Notes |
|---|---|---|
| sender | `h2._a6-h` | display name as shown in the app (may include emoji) |
| content | `div._a6-p > div` | a row of slots, below |
| time | `div._a6-o` (Instagram) / `footer._a6-o > div._a72d` (Facebook) | `Sep 08, 2025 10:15 am` on Instagram (minutes), `Jun 10, 2025 10:15:03 pm` on Facebook (seconds); no zone |

Content slots (Instagram and Facebook use the same ones):

| Slot | Shape | Read as |
|---|---|---|
| text | a `div` of inline content: text, `<br>`, `<a href>` | the message text; links become link entities |
| share card | `div > div > [div caption, div owner, div > a href]` | caption, owner and link appended as lines, link entity on the URL; the text slot then holds Meta's own line `X sent an attachment.`, kept under `ext.<platform>.generated` |
| media | `a > img`, `audio > a`, `video > a` with a local `src` | attachments (photos → image, `audio/` → voice, `videos/` → video) |
| call | `span._idm` "Duration: 3 minutes" (the text slot holds the call line) | `kind: call`, `call.durationSec`, `call.label` |
| reactions | `ul._a6-q > li > span` = `{emoji}{actor}<span> (Sep 08, 2025 10:16 am)</span>` | reactions with actor and time; the emoji is the first grapheme, the rest is the name (names can start with flag emoji) |

Observed on the Instagram download: 196 blocks whose slots are all empty (Meta exported nothing for them) and
one block with a sender and nothing else (no content, no time). They are kept as messages with
`meta.contentUnavailable`; the undated one takes the previous message's time and `meta.timeInferred`.

Facebook pages also carry `<aside>Generated by {owner} on <time datetime="2025-09-08T22:03Z">… UTC+02:00</time></aside>`:
the owner's name (used as "me") and the offset of the zone the page was written in, on that day.

### Times

HTML times have no zone. They are read in the converter's time zone (the machine's by default; the UI and
`--tz` change it), recorded in `meta.wallClockZone`. When a Facebook page states its offset and the chosen zone
disagrees on that day, the import warns. In the hour a DST change repeats, the instant that keeps the messages in
order is taken. The Instagram download kept one pair of messages 8 minutes out of order in its own order; the
converter keeps the download's order.

## JSON

`message_N.json`: `{participants:[{name}], title, thread_path, messages:[…]}`, newest first. Message keys:
`sender_name`, `timestamp_ms` (UTC), `content`, `photos/videos/audio_files/gifs/files:[{uri}]`, `sticker{uri}`,
`share{link, share_text, original_content_owner}`, `reactions[{reaction, actor, timestamp?}]`, `call_duration`,
`is_unsent`, `type` (`Generic`, `Share`, `Call`, `Subscribe`, `Unsubscribe`). Text is UTF-8 written as Latin-1
escapes (`Ã©` for `é`) and is re-decoded. Messenger's end-to-end-encrypted export uses camelCase keys
(`senderName`, `timestamp`, `text`, `media`, `isUnsent`, `threadName`); both are read. When a thread has both
HTML and JSON pages, JSON is used.

## The account owner

Facebook HTML names the owner in the page footer. Otherwise the owner is the name present in at least 60% of the
threads (89 of the 92 Instagram threads matched; the other three have only the other person's messages).

## What the download leaves out

Observed on the Instagram download: 196 messages with every slot empty, and 15 share cards holding only an
owner's username (no link or caption). Meta does not say why; they are kept as they are. Instagram's HTML shows
times to the minute; the JSON download carries milliseconds.
